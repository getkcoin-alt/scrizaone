# ScrizaOne organic growth — first execution cycle

Started 4 November 2026. Owner: Scriza Private Limited. Source baseline: BASELINE.json. This plan is implemented alongside code, resources and tests; it does not imply rankings, traffic, enquiries or revenue already exist.

## What this release builds

- Canonical origin matches Vercel's actual apex-to-www redirect. Sitemap, language alternates, organization links and llms.txt follow that origin.
- A single evidence-led research hub covers 20 markets with source links, dates and explicit confidence/unknown fields. It is a structured first scan, not a market-share study or proven top-20 revenue ranking.
- Six technical resources connect local payment access, engineering reliability and controlled AI deployment. They explicitly separate operator facts, proposed designs, synthetic examples and completed client evidence.
- A free, browser-local payment integration planning tool exports a useful brief. No email gate, artificial price estimate or misleading compliance score.
- Original MIT-licensed event-handling example and executable tests. No regulated access, transfer of money or production connector.
- Company/evidence and privacy pages, internal links, Article/Service/Breadcrumb metadata and a generated social image.
- Optional consent-gated GA4 instrumentation. With no property ID configured, it sends nothing and shows no consent bar. This is installed measurement infrastructure, not an active data baseline.

## Markets and sequencing

The full dataset is public/research/markets.json. Twenty countries: United States, Canada, United Kingdom, Germany, France, UAE, Saudi Arabia, Singapore, Australia, Japan, India, Brazil, Mexico, South Africa, Nigeria, Kenya, Indonesia, Philippines, Malaysia, Bangladesh.

The sequence weighs documented integration primitives, source quality, buyer-language readiness, sponsor access and fit with published capabilities. It does not use invented search volume or market size.

First investigation group: US, UK, UAE, Singapore, Australia, Nigeria, Kenya. Canada is gated by RTR rollout verification. European, Latin American and Asian expansion needs native-language review and validated procurement language. India retains a separate scriza.in commercial path; Indian terminology is not exported.

Classes: A = inferred commercial-intent implementation candidate; B = unknown search demand; C = unknown competition; D = infrastructure-change hypothesis; E = strategic engineering authority. Never turn B or C into a claim of high volume or low competition without data.

For the next research pass, capture locale/device/date and inspect local result pages for each seed. Record operator terms, actual competing URLs, language, query intent and whether results represent API documentation, regulated providers or engineering procurement. Search-engine results are not search-volume data. Native reviewers should validate Arabic, German, French, Portuguese, Spanish, Japanese, Bangla and Bahasa phrasing before localized pages are published.

## Content architecture and publication gate

Existing regional service pages remain working. The research hub is one reference rather than twenty templated sales pages. /resources contains curated implementation guides; /tools contains tested practical assets. Guides link to primary sources, related engineering and relevant services. Only build a new local-language or country commercial page after it offers materially different, verified local utility.

Each published resource needs: a real audience/task; primary sources and review date; distinction between facts and inference; honest authorship; applicable limitations; tested code where present; a correction route; relevant service links. No fictional human authors, client metrics, certificates, local offices or provider partnerships.

Translations: use independent crawlable URLs after native review, reciprocal hreflang only for genuinely equivalent translations, self-canonicals and an explicit x-default. Never force IP redirects or swap indexed copy under one URL. English research seeds do not justify multilingual hreflang.

Search and AI: keep content server-rendered, accessible and internally linked. Crawl allowances do not guarantee recommendations. OAI-SearchBot differs from GPTBot; Claude-SearchBot differs from ClaudeBot. llms.txt is an optional navigation aid. No extra AI schema, keyword stuffing or paid mentions. Keep structured data consistent with visible content.

## Measurement and exact access gaps

1. Create/use a free GA4 property for www.scrizaone.com. Add its public G-... ID as NEXT_PUBLIC_GA_MEASUREMENT_ID in the intended Vercel environment and redeploy. No tracking begins without visitor consent. Disable Google Signals, advertising integrations and all automatic enhanced-measurement collection, including history-based pageviews, forms, site-search and outbound clicks; the reviewed code emits only coarse allowlisted events and clean paths. Do not buy analytics add-ons.
2. Verify the domain in Google Search Console using the owner's DNS verification flow, or an authorized URL-prefix property. If using HTML verification, GOOGLE_SITE_VERIFICATION is supported. Submit the canonical sitemap after verification. The session cannot claim this is done without property access.
3. Verify Bing Webmaster Tools. BING_SITE_VERIFICATION supports the msvalidate.01 meta tag. Submit the same sitemap. An IndexNow integration is optional and must not be described as Google submission.
4. Provide read-only property access or export data for query/page/country/device/date. No connector requiring payment is purchased. Search clicks, impressions and indexing stay unknown until authorized data is supplied.
5. Maintain a sales/CRM record for actual received enquiries, qualification and closed revenue. Email composition and contact clicks are not received leads. The mailto form provides no server-side delivery receipt. Mail/CRM integration requires an approved provider and authorized credentials, configured in Vercel—not pasted into git.
6. Vercel Web Analytics is currently disabled. SDK insertion alone would not create historical data. No paid upgrade is enabled.

## Definitions

- Qualified international enquiry: a received, non-spam business enquiry outside India, within an actual service capability, with an identifiable business problem and a viable next step. A human records qualification and disqualification reason.
- Organic demand: source-supported search/community/editorial referral with a preserved attribution record; never infer organic revenue from a contact click.
- AI referral: observed AI-platform referrer when available. It omits untagged/copied links and says nothing about recommendation or citation.
- Verified AI mention: capture platform, prompt, date, locale, response excerpt and cited URL. A single observed response is not persistent rank or guaranteed coverage. Do not automate scraping of signed-in AI accounts.
- Non-branded visibility: Search Console queries excluding Scriza/ScrizaOne spelling variants, using a documented reproducible filter. Privacy-limited query rows may be omitted; document coverage.
- Lead conversion rate: qualified received enquiries / attributable eligible sessions, only when both exist and windows match. Otherwise unknown.
- Revenue: closed revenue matched to lead source with the agreed currency/time window; deduplicate deals. Show original currency or an explicit conversion method.

## 30 / 90 / 180 / 365-day gates

No numeric traffic or revenue promise is justified by today's unknown baseline. Establish 28 complete days of reliable analytics plus Search Console and sales records before selecting demand targets.

| Horizon | Operational target | Commercial target rule |
|---|---|---|
| 30 days | Verify properties, submit sitemap, run weekly audits; instrument and QA the funnel; validate the first 7 market hypotheses with actual queries/enquiries or authorized buyer conversations; fix broken indexing paths | Establish baseline and attribution coverage; do not label missing observations zero |
| 90 days | Keep content only where evidence supports audience utility; publish at most 2 deeper resources/month; run one organic tool/content experiment at a time | Set a documented qualified-enquiry improvement target against the complete 28-day baseline; if baseline is zero, use absolute counts from pipeline capacity rather than percentages |
| 180 days | Expand 2 validated clusters; obtain permissioned, measurable delivery evidence; maintain tests and corrections | Compare rolling 90-day qualified enquiries and opportunities by market/service; continue only segments that show fit |
| 365 days | Assess revenue, lead quality, repeat use and maintenance cost; retire low-value content; add translations only with evidence | Set the next annual demand target from actual close rate, delivery capacity, sales cycle and organic-attributed revenue |

First baseline-review meeting should choose the actual numbers and record rationale, uncertainty, review date and owner in targets.json. Do not retroactively claim pre-instrumentation growth.

## Organic distribution, without unsolicited messages

Prepare useful technical contributions for communities only where their rules permit them. Contribute the tested reference code, answer a specific integration question and disclose affiliation when relevant. The current authorization does not require sending emails, DMs or posting to other people's channels; draft those contributions for review. No backlinks purchases, link exchanges, fake reviews, artificial traffic, ad campaigns, paid placements or sponsored articles.

## Weekly operating loop

Read production and current main first. Run the technical audit, inspect available real analytics/search/sales data, refresh changed primary sources, review one highest-impact failure, and record findings. Keep the baseline and missing-access status explicit. A scheduled weekly review is configured separately; it is not an always-running autonomous agent and cannot measure disconnected sources.

## Rollback

Before publishing, record parent commit and deployment ID. To revert code, create a normal revert commit against the release; preserve later work and never force-push. If urgent, use Vercel's previous verified production deployment, then reconcile Git. This release does not change payment operations or introduce a server-side lead database.

## Why the first tool is an integration planner

| Candidate | Evidence available now | Decision |
|---|---|---|
| Country-aware payment integration planner | FedNow, PayTo, NIP and Daraja source material shows access, onboarding and operational boundaries that an engineer must clarify | Build first: captures real scope questions, gives an ungated export and connects naturally to existing services |
| Software price estimator | No validated delivery-cost model, scope distribution or local pricing baseline | Defer: a generic numeric range would invent precision |
| AI ROI calculator | No observed customer process time, error cost or implementation baseline | Defer: first publish an evaluation contract and gather authorized pilot measurements |
| Full country opportunity score | No verified keyword volumes, competition or country-specific buying data | Do not score yet; publish an evidence map with unknowns |

The planner is a usefulness hypothesis, not a proven acquisition winner. Evaluate actual usage, received enquiries and qualification before expanding it.
